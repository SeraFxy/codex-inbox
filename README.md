# codex-inbox · AI 任务台账

同时开很多个 Codex / Claude Code 会话时，很容易忘了哪个在等你回话、哪个在等同事、哪个今晚要发版。codex-inbox 是一个跑在你 Mac 上的本地看板：它读这两个工具留在本机的对话记录，按「现在等谁」把会话分好组，到点弹通知，还把你说过的话、AI 给你的链接和文件、你发过的图片另存一份。

English: [README.en.md](README.en.md)

*A local macOS dashboard for people who run many Codex and Claude Code sessions at once. It reads the transcripts both tools already keep on disk, groups sessions by who they are waiting on, notifies you when something is due, and keeps a searchable copy of what you asked. No AI calls, no tokens, nothing leaves your machine. The UI is in Chinese.*

名字里只写了 Codex 是为了好懂，**Codex（桌面版和 CLI）和 Claude Code 都支持**。

## 让 AI 帮你装

把下面这句话发给你的 Claude Code 或 Codex，它会按 [INSTALL.md](INSTALL.md) 把安装和设置做完，只在需要你本人动手时（浏览器里授权、系统弹窗点允许、同意改安全设置）停下来问你：

```text
帮我安装 codex-inbox：https://github.com/SeraFxy/codex-inbox ，按仓库里的 INSTALL.md 一步步做完
```

想自己动手，看下面的「安装」。

## 它能做什么

- **按「现在等谁」分组**：四个标签页：轮到你（现在需要你、待你确认完成）/ AI 在做 / 在等（等时间点、等同事）/ 待整理，点一条右边出详情。键盘 J / K 上下，O 打开会话，E 完成，S 推迟，P 置顶，[ 收起或展开左栏，⌘K 搜索。置顶的排在最上面，其余按更新时间，新的在前。分组依据是 AI 每条回复最后写的一行状态（见下面的「状态行」），没写状态的会话也会列出来，标成「状态不明」。
- **按项目和主题筛选**：最左边一栏列出项目，项目下面可以建主题（比如一个项目下面的「客户A」「评测」），点哪个中间就只剩它的会话；红色数字 = 里面有轮到你的事。会话归到主题有三种办法：在发给 Claude / Codex 的消息开头或结尾写 `#主题`，后面空一格（或在哪都写成 `#主题#`），以最后写的为准，没有这个主题就在该项目下新建一个；夹在句子中间、代码里的 `#xxx` 只认已有的主题，不会新建；把列表里的行拖到左栏的主题上；点行上的「⋯」→「归到主题…」。手动归的优先，之后消息里的 `#主题` 不会再改它。主题可以改名（以前写的 `#旧名` 还认得）和删除。会话默认按所在文件夹算项目；放错了（比如通用的每日定时任务建在了某个项目的文件夹里），点行上「⋯」→「移到项目…」或把行拖到左栏的项目上，可以移到别的项目，也可以打字新建一个（比如「定时任务」），之后随时移回。项目名取的那层文件夹不合适，就在详情「会话信息」的「位置」里点路径中的一段：以后在这个文件夹里开的会话都按这一层归项目，点错了能撤销，也能点「恢复默认」。双击项目或主题改名；拖项目换位置；项目和主题的「⋯」里可以归档：归档的不进「全部」，在左栏最下面的「归档」里看，里面的会话再有新动静就自己回来。会话可以收藏（行上「⋯」或详情右上角的星标），放在左栏「收藏」里，完成了也留着，点一下找到或直接打开。会话可以改名（双击详情里的标题，或行上「⋯」→「改名…」），Claude / Codex 里和 cmux 标签页一起改，只追加一条改名记录，不调 AI。页头可以只看 CC 或 Codex 的会话。Codex 定时任务在跑的会话标灰色的「定时」，悬停看是哪个定时任务、什么时候跑，暂停了的标浅一点；这些会话还会自动列在左栏的「定时任务」里（和「收藏」同级，不管在哪个项目），右边写什么时候跑，暂停了的收在「已暂停的 N 个」里。
- **卡住了也能看出来**：AI 停在一个提问或待批准的操作上、你发的消息半小时没回、停在半路很久没动静，都会排到「现在需要你」。
- **到点提醒**：状态行带了将来的时间，就先放在「等时间点」，到点挪到「现在需要你」并弹 Mac 通知，点通知打开看板。每张卡可以推迟 15 分钟、1 小时、3 小时、到今晚、到明早、3 天后（早上 9 点）或下周一。
- **待你决定**：AI 在回复里用 `❓ 事情｜选项｜选项` 列出要你拍板的事，这时卡片按「等你」排（就算它说已经达到完成标准），展开卡片就能逐件点选项，看板拼成一条回复（没选的写「待定」），回复框里能直接改。AI 在那一行加了「荐：」写明推荐哪个、为什么，推荐的选项标个「荐」并默认选上，理由写在问题下面；改过选项又想按推荐的来，点「全按推荐」。看板会记着之前问过、你还没答的事：卡片上标「N 件没答」，详情里列在「之前问过、还没答」下面，能接着选，也能点「不用答了」收起来。你回复里按「1. 事情：选项」答了、或提到它的编号（如 Q-031），就算答了；问题照抄、后面的编号不抄也行，问题和答复之间用冒号、竖线、空格、下划线、破折号隔开都认；它再问同一件，会重新列出来。点「复制并打开会话」，回复复制到剪贴板、会话也打开了，你自己按 ⌘V 回车发出去。看板不替你发：每发一条，AI 都要把整段对话重读一遍，什么时候发由你决定。它写「等你」、又没有要你拍板的事时，是要你去做一件事：卡片上写「要你做：…」，详情里单列「要你做」，做完了点「做完了，你接着做」回它一句，它才会接着做。
- **它替你定的**：AI 没问你、自己拿了主意的事，按 `🧭 定了什么｜为什么` 写一行，卡片上标「替你定了 N 件」，详情里「它替你定的」列出最近 20 件，新的在前。不同意就点「改」：复制「关于你替我定的「…」，我想改成：」并打开会话，你接着写想怎么改。
- **上下文占用**：按对话记录里每次回复的用量，算出上下文用了百分之几，不调 AI。用到 70% 时，行上标「上下文 N%」，详情里提醒一句「这件做完换个新会话接着做」；会话信息里一直能看到百分比。Claude 会话按 `~/.claude/settings.json` 里给这个模型设的 `autoCompactWindow`（用到这么多就自动压缩）算，没设按 20 万；Codex 会话按它记录里的上下文窗口算，和 Codex 界面上的数对得上。
- **压缩时的交接**：Claude 会话上下文满了会压缩，压缩时它给自己写一段交接（目标、做到哪、还剩什么），长会话光看第一句和最后一句看不出全貌，看这段就清楚。看板把最后一段放在详情「对话」下面，默认只露前几行，原文照放，不调 AI。状态行规则里约定了交接用中文写；以前写的英文交接可以点「翻译成中文」，用浏览器自带的翻译（Chrome 138 起）在本机翻，不花 token，翻好的存在这台电脑的浏览器里。Codex 的压缩摘要是加密存的，读不出来，所以只有 Claude 会话有。
- **「我说过的话」**：你发给 Codex / Claude 的每一句话按会话归组，支持多关键词搜索、逐句复制。Claude Code 默认 30 天后删对话记录，这里另存一份纯文本（一年约 20MB）。
- **一个搜索框搜两边**：⌘K 或 / 先进「全部」：AI 给的产出物（前 3 个）和你说过的话一起列，Claude 压缩时的交接、AI 问你的事（❓，答过的也算）、它替你定的事、状态行和目标也一起搜，结果里标明是在哪对上的，不用先想清楚是你说的还是 AI 给的；只看一边就点「我说过的话」或「产出物」，三个标签共用一个搜索词，切换不清空，标签上写命中几个。每条命中旁边点「前后对话」，就在结果里展开那一句前后你和 AI 说的话（你说的每一句，加它每一轮最后的回复），搜索词标亮，可以接着往前、往后看；对话记录已经清掉的，只剩台账记下的那句和你前后说的话。搜索页左上角「‹ 看板」或按 Esc 回看板。
- **产出物**：AI 在回复里给你的链接（飞书文档、MR、GitHub 等）和本机文件（写成路径或 `[名字](路径)` 的 Markdown、网页、PDF、表格、图片等，文件得真的在），代码块和命令行里的不算。产物（文档、文件、网页）一直留着；MR、流水线、提交是临时的，单独放在「MR 和流水线」一组，不算产物。页头「产出物」里能按飞书 / 文件 / 网页 / 代码筛选、按标题、链接、AI 的原话、会话名搜，同一个链接只列一次；每条带着 AI 给出它时说的那句话和给过它的会话，点会话名回到看板打开它的详情（不在看板上的直接打开会话）。本机文件点一下用默认应用打开；文件所在的 git worktree 被清理了，就打开主工作区里的同名文件（主工作区不在默认分支上时，改开 GitLab / GitHub 上默认分支的版本）。会话详情里列最近 8 个产物，可以展开全部、在里面找；下面单列这个会话的 MR 和流水线，只摊开还开着的 MR，合并完的收起来。装了 lark-cli 并以你的身份登录时，飞书文档显示真实标题（每批 200 篇调一次飞书接口，不调 AI；配置 `feishu_doc_titles` 设成 `false` 可关掉）。装了 glab 并登录了你们的 GitLab 时，MR 显示真实标题和「待合并 / 已合并 / 已关闭」，「还开着的 MR」里只列没合并的（按项目每 40 个查一次，开着的 15 分钟再查一次，不调 AI；`gitlab_mr_state` 设成 `false` 可关掉）。
- **产出物留档**：AI 给你的本机文件，每一版都在看板里存一份（按内容去重，单个超过 50 MB 的不存），原文件删了、改了也打得开老版本；搜索也搜它的标题和正文开头（Markdown 的第一个标题、网页的 `<title>`、表格的表头）。macOS 不让后台服务读「桌面」「文稿」里的文件内容，所以留档由 AI 那边做：`<安装目录>/ledger hooks install` 给 Claude Code 和 Codex 各加一个 Stop 钩子，每轮结束时把这一轮提到的文件复制进 `data/archive/`（Codex 还要在「设置 → Hooks」里点一次 Trust；`ledger doctor` 会查出没装或没点）。以前给过的文件，运行一次 `<安装目录>/ledger archive --backfill` 补上。
- **审阅页**：AI 要你在网页上逐条审（审核页、判定页）时，写一行带编号的 ❓ 并给链接；回复里只给了一个网页链接时，看板在那件 ❓ 旁边放「打开审阅页」，一点就开，不用往对话里找。你把页面上复制的反馈贴回会话（第一行带编号），这件就算答了；没答之前一直挂着，会话留在「轮到你」。
- **另存目标和图片**：Codex 的 goal、状态行里的 🎯 目标、你发给 AI 的图片（按内容去重）。原会话被删了也还在。「我说过的话」里搜到的会话可以点「在看板里看」，回到看板看它的现状、目标和产出物。
- **点「完成」不会弄丢**：完成的会话挪到最下面，你再和它说话，它会自动回到看板。
- **在 cmux 里关掉标签页就算完成**：不用两边各点一次，看板下次刷新时会把它挪到「已完成」。已定时、等同事、等时间点还没到的不动（多半是先关掉省内存，到点还要提醒你）。之后在 cmux 里重新打开，它会回到看板。反过来也一样：在看板上点「完成」或「不再跟踪」，它在 cmux 里的标签页也会关掉，开着的标签页就都是还要跟的。AI 还没停下来（在跑、在等你批准）的不关；工作区里还有别的标签页（比如浏览器）就只关它自己；分组的标题标签不动。撤销完成后想接着聊，点「打开会话」在 cmux 里重新打开。
- **会话名和标签**：会话名优先用你在 cmux 终端的侧边栏里手动改的名字；项目短码可以改名字、加 emoji（项目一律灰色，颜色只用来表示状态）。
- **可选功能**（需要另装工具，没装就用不了，其他功能不受影响）：
  - 定时唤醒：在 cmux 终端里跑的 Claude 会话，可以用 `ledger schedule` 让它到点自己继续（比如晚上发版）。需要 cmux，且要在 cmux 设置里允许后台程序控制它（`ledger cmux-setup`，见「已知限制」）。
  - 飞书每日汇总：装了飞书命令行工具 lark-cli 并在配置里填了 `feishu_open_id`，每天早上把汇总私信给你。`ledger feishu-setup` 会替你填好并发一条测试。

全部是读本机文件，**不调用任何 AI，不花 token**。服务只监听 `127.0.0.1`，网络请求只有可选的飞书汇总和飞书文档标题。

## 安装

需要 macOS，用系统自带的 `/usr/bin/python3`（3.9 及以上），不需要装任何依赖。

```sh
git clone https://github.com/SeraFxy/codex-inbox.git ~/codex-inbox
~/codex-inbox/install.sh
```

然后打开 <http://127.0.0.1:47800>，建议固定在浏览器标签栏。装完运行 `~/codex-inbox/ledger doctor`，它逐项检查安装（只读），没装好的会告诉你下一步。

- **不要装在「桌面」「文稿」「下载」里**：macOS 不让后台服务读这几个目录，`install.sh` 会拦住并提示。
- 安装会注册一个开机自启的 launchd 服务（默认名 `local.codex-inbox`，可以用环境变量 `CODEX_INBOX_LABEL` 改），并编译一个叫「AI 任务台账」的通知小程序。装完会弹一条欢迎通知，macOS 问要不要允许它发通知时点允许。
- 更新代码后再运行一次 `install.sh` 就会重启服务；`uninstall.sh` 停止并移除服务，数据留在 `data/`。

## 让 AI 写状态行

看板靠 AI 每条回复最后一行的状态来分组。规则写在 [status-line.md](status-line.md)，装好后运行一次：

```sh
~/codex-inbox/ledger rules install
```

它把规则加到 `~/.codex/AGENTS.md`（Codex）和 `~/.claude/CLAUDE.md`（Claude Code）的末尾，前后用 `<!-- codex-inbox:status-line:start -->` / `<!-- codex-inbox:status-line:end -->` 标记包好，「已定时」要用的 `ledger schedule` 会换成你本机的完整路径。只给装了的工具加；文件里已经有你手写的状态行规则（含 `📌 <状态>`）就跳过。更新代码后再运行一次会原地更新；`ledger rules show` 预览，`ledger rules remove` 只删标记之间的内容。新开的会话才会按规则写。

手动加也行：把 status-line.md 开头说明注释以下的内容复制进上面两个文件，把 `{{LEDGER}}` 换成 `<安装目录>/ledger`。

## 配置

第一次安装会从 `config.example.json` 复制出 `config.json`，改完运行 `install.sh` 生效。可以写的项（都有默认值）：

| 项 | 默认 | 说明 |
|---|---|---|
| `port` | `47800` | 看板端口 |
| `scan_interval_min` | `15` | 后台多久读一次对话记录；看板网页开着时每分钟也会读一次 |
| `window_days` | `14` | 只看最近多少天有动静的会话 |
| `stale_hours` | `48` | 多久没动静算「待整理」 |
| `interrupted_min` | `30` | 停在半路多久算「可能卡住了」 |
| `digest_time` | `"09:00"` | 飞书汇总的时间 |
| `feishu_open_id` | 空 | 你的飞书 open_id；空着就不发汇总 |
| `feishu_as` | `"bot"` | 用 lark-cli 的哪种身份发 |
| `wake_expire_hours` | `3` | 定时唤醒晚了多久就放弃（比如 Mac 一直在睡） |
| `utc_offset_hours` | 空 | 看板按哪个时区算时间，空就用本机时区。Mac 的时区和你安排工作的时区不一样时填，比如人在国外但按北京时间工作就填 `8`。状态行和 `ledger schedule` 里的时间也按它理解 |
| `project_parents` | `[]` | 这些目录下的每个子目录算一个项目，比如 `["~/code", "~/work/repos"]`。不填时按 `~/Desktop/<项目>`、`~/<项目>` 推断；`~/Documents`、`~/Documents/ChatGPT`、坚果云（`~/Nutstore Files/Nutstore`）、`~/Dropbox` 这类收纳文件夹自动往下取一层。几个目录套在一起时按最里面那层算，比如再配一个 `~/Nutstore Files/Nutstore/<分类>`，这个分类下的子目录就各算一个项目。Codex 开的工作树（`~/.codex/worktrees/…`）归到主仓库所在的项目，`~/Documents/Codex/<日期>/` 这类临时目录归「其他」 |
| `feishu_doc_titles` | `true` | 产出物里的飞书文档用 lark-cli 以你的身份查真实标题；`false` 就只用 AI 写的说明 |
| `gitlab_mr_state` | `true` | AI 给的 GitLab MR 用 glab 以你的身份查标题和合并了没有；`false` 就不查 |

## 常用命令

```sh
./install.sh                 # 安装或重启服务
./uninstall.sh               # 停止并移除服务
./ledger scan -v             # 手动扫一次，打印各组
./ledger schedules           # 最近的定时唤醒
./ledger cancel <编号>        # 取消定时唤醒
./ledger digest              # 预览飞书汇总（--send 发送）
./ledger doctor              # 体检：逐项检查安装，给出下一步（只读）
./ledger rules install       # 加状态行规则（remove 删掉，show 预览）
./ledger hooks install       # 加产出物留档钩子（remove 删掉，show 看装没装、Codex 点没点信任）
./ledger feishu-setup        # 设置飞书每日汇总并发一条测试（--dry-run 只看不做）
./ledger cmux-setup          # 让看板服务能控制 cmux，定时唤醒要用（--dry-run 只看不做）
```

## 读了哪些文件、存了什么

| 来源 | 用途 |
|---|---|
| `~/.claude/projects/*/*.jsonl`、`~/.claude/history.jsonl` | Claude Code 会话、你发过的话和图片 |
| `~/.claude/sessions/*.json` | 开着的 Claude 会话此刻在跑、空闲，还是弹着批准框在等你 |
| `~/.codex/sessions/`、`~/.codex/*.sqlite`、`~/.codex/session_index.jsonl` | Codex 会话、标题、goal、你发过的话和图片 |
| `~/Library/Application Support/cmux/session-*.json` | cmux 侧边栏里改过的会话名（只读） |

存在安装目录里（都不进 git，`data/` 和 `logs/` 只有你自己的账号能读）：`data/ledger.db`（会话状态、你的操作、主题、你说过的话、目标、产出物）、`data/images/`（图片，几百张约一两百 MB）、`data/archive/`（产出物留档，几百个文件约几百 MB）、`logs/`、`config.json`。

## 测试过的版本

在下面这套环境里实际用过；别的版本大概率也能用，但没测过：

- macOS 26.5，系统自带 Python 3.9
- Codex 桌面版（ChatGPT.app 26.1023.51421，内置 codex-cli 0.165.0-alpha.1.2）
- Claude Code 2.1.312

Codex 部分读的是它的内部文件，文件名里带版本号：`~/.codex/state_5.sqlite`（会话来源和标题）、`goals_1.sqlite`（goal）、`thread_history_1.sqlite`（你发过的话、AI 回复里的链接），以及 `session_index.jsonl` 和 `sessions/` 下的对话记录。Codex 升级后如果这些文件改了名字或结构，相应的功能（标题、goal、「我说过的话」里的 Codex 部分）可能读不到，日志里会有提示；看板分组靠的是 `sessions/` 下的对话记录，一般不受影响。

## 已知限制

- 只看最近 14 天有动静的会话；AI 自己调起的子任务不进看板：子代理、审查代理、`claude -p`、`codex exec`，以及别的 AI 通过 MCP 调起的 Codex。挂了 Codex 自动任务（心跳）的线程是你自己开的，照常进看板；每日提醒这类不想看的，点一次「不再跟踪」就不再出现。
- 「打开会话」：Codex 会话用 `codex://threads/<id>` 打开；Claude 会话要跳到 cmux 里的对应窗口，但 cmux 默认只允许在 cmux 终端里启动的程序控制它，开机自启的看板服务会被拒绝，这时看板只会提示，不会替你另开一个会话；定时唤醒也受同样的限制。要放开，把 cmux 改成密码模式：在 `~/.config/cmux/cmux.json` 里加上 `"automation": {"socketControlMode": "password", "socketPassword": "<随便一串长密码>"}`，再运行 `cmux reload-config`（也可以在 cmux 设置 → 自动化里改「套接字控制模式」并设密码）。新版 cmux 会把这个密码从 cmux.json 挪进它自己的设置，开机自启的服务读不到，所以看板另存一份在 `data/cmux-password`（只有你的账号能读），每次调 cmux 时带上。`ledger cmux-setup` 可以替你改模式（文件带注释时它只打印说明，不硬改），再让你粘贴一次 cmux 设置里的套接字密码；哪天看板又跳不过去，重新跑一次它就行。
- Mac 睡眠时服务也在睡，通知和定时唤醒在醒来后补上；晚了超过 `wake_expire_hours` 的唤醒不再执行。
- 看板的读取接口没有设密码：网页打不开它（服务会核对来源），但这台 Mac 上的程序都能读到会话列表、你说过的话和图片。改动操作（标完成、推迟、改标签等）需要令牌。用你自己账号跑的程序本来就能直接读 `data/` 里的数据库，加密码也挡不住；如果这台 Mac 还有别人的登录账号，请留意这一点。
